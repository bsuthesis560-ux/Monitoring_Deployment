There are several major system revisions and feature enhancements that need to be implemented.

## 1. Removal of Vehicle Plate Features

The vehicle plate number functionality will be completely removed from the system, including:

* Vehicle plate number registration
* Vehicle plate display in the Staff Monitoring Dashboard
* Vehicle plate column in the Attendance Logs page
* Vehicle plate column in the Personnel Roster page

The system should now focus entirely on personnel monitoring and attendance management.

---

## 2. Attendance Log Page Revision

The Attendance Log page should be updated to display only the following fields:

* Employee Name
* Employee ID
* Department
* Position
* Date & Time
* Log Type (Time In / Time Out)

The attendance records should be properly organized and optimized for monitoring and reporting purposes.

---

## 3. Replace “Camera” Option with “Record Summary”

The existing “Camera” option/function should be removed and replaced with a new section called **Record Summary**.

### Record Summary Functionality

The Record Summary module should automatically categorize and organize attendance records into:

* Daily Records
* Weekly Records
* Monthly Records

---

### Daily Record Collection

Attendance logs generated throughout the day should be collected and stored as a separate daily record.

Example:

```text id="5d1x7m"
Daily Record → May 18, 2026
```

At the start of the next day:

* A new daily record should automatically be created
* Previous daily records must remain archived and accessible

This process should continue automatically every day.

---

### Weekly Record Collection

Once daily records accumulate for an entire week:

* The system should automatically group and consolidate them into a Weekly Record section
* Weekly records must remain archived and accessible for future retrieval

Example:

```text id="z7n1cw"
Weekly Record → Week 3 of May 2026
```

---

### Monthly Record Collection

Weekly records should also be consolidated into Monthly Records.

Requirements:

* The specific month and year must be clearly indicated
* Monthly summaries should remain separated and archived properly

Example:

```text id="dhf0mu"
Monthly Record → May 2026
```

---

### Record Template Requirement

Use the provided file/template as the basis for formatting collected records.

The following mappings must be applied:

* Employee names should populate the:

  ```text
  NAME
  ```

* Attendance timestamps should populate the:

  ```text
  DATE & TIME
  ```

The formatting and structure of the generated records must follow the provided template consistently.

---

### Department-Based Separation

All records within the Record Summary module must be separated by department to avoid mixing attendance data across different offices or units.

Example:

* HR Department Records
* ICT Department Records
* CET Faculty Records
* Admin Department Records

Daily, weekly, and monthly summaries should all maintain department-based categorization.

---

## 4. Employee Update Functionality

Add an **Update Employee** option for all registered personnel.

### Update Workflow

The update process should function similarly to the current employee registration workflow:

1. User selects an employee to update
2. System redirects to the Register Personnel page
3. Existing employee information is automatically pre-filled into the form
4. Administrator can modify or add new information
5. The action button should display:

   ```text
   UPDATE
   ```

   instead of:

   ```text
   REGISTER
   ```

This feature should support standard employee information editing while maintaining the existing registration structure and validation logic.
