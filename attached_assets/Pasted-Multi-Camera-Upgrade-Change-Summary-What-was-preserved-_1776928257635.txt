Multi-Camera Upgrade — Change Summary
What was preserved
Every piece of core logic from the original is untouched — preprocess_face_roi, fast_detect_faces, FaceTracker, download_registered_photos, all recognition constants (ArcFace, threshold 0.55, vote buffer), cooldown logic, and API endpoints are identical. The upgrade is purely additive.

What was added and why
CameraConfig dataclass + load_cameras_from_env()
Replaces the single hardcoded RTSP_URL with a structured config object per camera. Credentials are loaded from .env via python-dotenv, so no sensitive values ever touch source code. The loader scans for CAM1_*, CAM2_*, CAM3_* groups automatically — adding a third camera requires three lines in .env and nothing else. Switching from home to campus network is a config change, not a code change.
CameraWorker class
Encapsulates the full lifecycle of one camera: its HikvisionStream, FaceTracker, AI worker thread, and per-camera cooldown table. Each worker runs on its own daemon thread with no shared mutable state between cameras. A network drop on Camera 2 triggers only that camera's reconnect logic — Camera 1 is completely unaffected.
HikvisionStream — thread-safe frame buffer
Added a threading.Lock around the frame write/read path. In the original single-camera design this wasn't necessary; with multiple threads reading frames concurrently it is.
_get_dnn_detector() — thread-safe lazy load
Added a threading.Lock around the DNN model initialisation so that two camera threads starting simultaneously don't both attempt to load the Caffe model, which would cause a race condition.
Camera source tagging
submit_log() accepts an optional camera_name parameter and includes it in the JSON payload as cameraName. The existing API endpoint ignores unknown keys, so this is fully backward-compatible. Console output now follows this format:
[Logged]  Name: Juan Dela Cruz | Camera: Camera 1 | Time: 08:01 AM | Type: TIME IN
build_display_frame()
Composes per-camera annotated panes into a single tiled window. Layout collapses gracefully: one camera renders full-size, two renders side-by-side, three or more wraps into rows of two. Each pane carries its own face overlays, confidence scores, and an ONLINE/OFFLINE status bar. A global FPS and camera-count overlay sits at the bottom of the composed frame.

Setup
bash# Install the one new dependency
pip install python-dotenv

# Copy the env template and fill in values
cp .env.example .env

# Run
python facial_recognition_service.py
Your two cameras are already pre-filled in .env.example with the IPs and passwords you provided. Add .env to .gitignore before committing.
