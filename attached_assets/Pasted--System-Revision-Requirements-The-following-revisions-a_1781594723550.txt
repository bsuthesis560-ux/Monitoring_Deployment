# System Revision Requirements

The following revisions and enhancements need to be implemented across the Personnel Monitoring System.

## 1. Personnel Registration Form Revisions

### Form Content Updates

* Remove or replace the statement:

  > "I agree to the terms and conditions and verify this information is accurate."

* Rename the field:

  * **Middle Initial** → **Middle Name**

### Employee ID Validation

The Employee ID field must follow the following rules:

* Maximum length: **5 characters**
* Accept **numbers only**
* Do not allow alphabetic characters
* Allow special characters, including "-"
* Input validation should prevent invalid characters during data entry

### Name Field Validation

All name-related fields (First Name, Middle Name, Last Name) must:

* Accept letters only
* Reject numbers
* Reject special characters
* Support standard suffixes such as:

  * Jr.
  * Sr.
  * II
  * III
  * IV

### Name Formatting Rules

The system should automatically standardize name formatting:

Example:

```text
Christian Lloyd Matricular Brito
```

The following formats should not be allowed to create separate records:

```text
christian lloyd matricular brito
CHRISTIAN LLOYD MATRICULAR BRITO
cHrIsTiAn LlOyD mAtRiCuLaR bRiTo
```

Names should be normalized before validation and storage.

### Duplicate Name Prevention

The system should prevent duplicate personnel registration based on the complete name.

Example:

Existing record:

```text
Christian Lloyd Matricular Brito
```

Attempts to register the same person using:

* Different capitalization
* Mixed uppercase and lowercase letters
* Minor formatting variations

must be rejected as duplicate entries.

---

## 2. Dashboard Filtering Enhancements

### Office-Based Filtering

Retain the existing College filtering functionality and add Office-based filtering.

Requirements:

* Selecting an Office should display a corresponding Sub-Unit dropdown when applicable.
* Each Office should display only its associated Sub-Units.
* Changing the selected Office should dynamically update the available Sub-Unit options.

Example:

```text
Office of the Chancellor
    └── Sub-Unit A
    └── Sub-Unit B
```

### Navigation Behavior

When a user selects:

* Office
* Sub-Unit (if available)

the system should automatically redirect to the corresponding Staff Monitoring page.

This functionality should apply to all offices and organizational units.

---

## 3. Record Summary Enhancements

### Summary Filter Options

Add filtering capabilities within the Record Summary module.

Users should be able to generate summaries based on:

* Date
* Time Range

Example filter options:

```text
Daily
Weekly
Monthly
Custom Date Range
Custom Time Range
```

---

## 4. Summary PDF Report Revisions

### Design Standards

The generated PDF reports must:

* Use the official university branding
* Maintain the original aspect ratio of logos
* Prevent stretched or distorted logos

### Attendance Layout

Each employee should occupy a single row containing:

* Employee Name
* Time In
* Time Out
* Continuous Attendance Records

This layout should provide a cleaner attendance summary structure.

### Weekly and Monthly Reports

For weekly and monthly summaries:

* Clearly display the covered date range in the report header
* Example:

```text
Weekly Summary
May 1 – May 7, 2026
```

```text
Monthly Summary
May 2026
```

### Date Display Rules

Within the summary table:

* Remove repetitive date entries from each attendance record row
* Retain only the report date or date range in the report header

This prevents redundant date information and improves report readability.

---

## 5. Personnel Management Enhancements

### Personnel Record Creation

Ensure the system supports complete personnel profile creation while maintaining all validation and duplicate-prevention rules.

All personnel information should be consistently validated before registration and update operations.

### Update Compatibility

All newly implemented validation rules must also apply when updating existing personnel records to ensure data consistency across the system.
